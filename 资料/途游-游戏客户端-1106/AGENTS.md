# 途游 · 游戏客户端（入口，先读本文件）

> 建立：2026-11-05。用途：途游 AI 深度参与游戏开发 / 客户端岗的面试准备和复盘。
> 本目录在 `practice` 仓库里，仓库根目录 `AGENTS.md` 的规则同样适用（特别是第三节「讲概念的方法论」）。

## 一、背景（一句话）

27 届，Java 后端 + Vue 前端的全栈背景，**没做过原生客户端和引擎**。途游一面（11-03，线下，技术负责人）已过；二面 **11-06（周五）10:00 线上，AI Coding 形式，不手撕**。HR 说岗位定位是**客户端开发**，项目组是**海外休闲类**（不是三冰等国内产品）。

完整经过、一面复盘、本人项目资料、公司调研都在 `途游全记录.md`。

## 二、给 AI 的规则

1. 先读完 `途游全记录.md` 再说话；不清楚的先问，不要编
2. 陪练时一次只问一题，等用户答完再追问；用户说「不知道」就直接按「讲概念的方法论」讲，讲完让用户重答，按重答打分
3. 项目按决策式讲：用 X 是因为 A、B，Y 作对照；对照方案不能说成已经实现
4. 客户端相关的问题：不教用户假装有引擎经验，教他用网页游戏里的对应物把问题接住（见记录 7.2 节）
5. 体验类例子只用用户真实做过的；用户没给的就留空，不替他编
6. 复盘只评内容，不挑用户复述时的措辞
7. 面完把复盘填进记录第九节，待办状态更新在第八节
8. 这是公开仓库：不写真实姓名、联系方式、HR 和同学的名字、薪资底线，不放公司内部信息；除了本目录下的文件不改别的；不许 `git add` / `commit` / `push`，要提交时由用户另行要求
