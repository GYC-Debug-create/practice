## 三、一面复盘（11-03，线下）

> 本人回忆的大致还原，不是原话。11-04 第一次复盘时误记成了另一家公司（柠檬微趣），以本节为准。

### 3.1 整体印象

- 没考八股，没手写代码，重点聊「怎么用 AI 做事、标准怎么定、怎么验收」
- 同场其他候选人停在「要不要用 AI」「AI 写的代码我负不负责、要不要写测试、能不能真正开发」；本人已经在讲「AI 深度参与时，怎么让产出标准化、怎么验收」，高一层
- 开场面试官评价本人「涉猎挺广」：从项目统筹到前端、后端（只是开场白，没有追问）
- 本人自评：本人用 AI 的方式和这家公司高度一致，只是流程完整度没那么高

### 3.2 逐题记录 + 补强答法

**① 公司的 AI 用法（面试官介绍，本人追问）**

- 他们的流程两头最重：**开头的文档**和**结尾的验证**，中间实现全交给 AI；文档也是 AI 深度参与写的
- 验证：让 AI 产出验收案例，案例要设计成**人一看结果就能判断质量**，最后输出一张清单，**全部打勾**才算完成
- 本人的差距：本人平时是**抽查** 1～2 条，他们是**全检**
- 补强讲法：把每条验收标准写成能直接判断对错的，AI 逐条自检、每条附证据，人抽查证据真假；最后清单全勾、证据可查，就是闭环

**② 模型怎么选（本人主动问的）**

- 本人提问：「全用最强模型 all in，还是综合考虑？」
- 本人举例：Opus 5.5 做规划，Sonnet 5.5 干活；换到 Codex 就是强模型规划、其他模型执行
- 面试官**当场认同**，说他们内部开发也是这么做的
- 下一轮可能追问「token 不限量（面试官提到过），为什么还要分模型？」，理由不能是省钱，换成：
  - **速度**：检索、抄录这类机械活，小模型快得多
  - **上下文干净**：主模型只做规划和验收，脏活交给子代理，主模型的判断不会被大量检索结果带偏
  - **交叉验证**：不同模型容易犯的错不一样，一个干活、一个验收，更容易抓到问题

**③ 企业为什么自己开发 agent（本人主动问的）**

- 本人提问：自己用下来一个编程 agent 加一个日常 agent 就够了，企业自研 agent 是跟风抢市场，还是结合自家生态？（本人事先判断对方不是做 agent 的才问）
- 面试官回答：**结合生态**，内部的知识库、打卡、日报等都要接进来，而且都要**授权**
- 这和本人实习做的 AI 问数 MCP 正好对上：用户先 OAuth 登录，服务用他的身份去查，所以只能查到本人权限内的数据
- 下一轮换个问法更稳：「我自己用下来一个编程 agent 加一个日常 agent 基本够用，所以想请教，公司专门做这些 agent，主要补的是通用 agent 做不到的哪部分？」

**④ 项目：TeamMatch，问「有没有考虑 1 万并发打进来」**

- 本人当时答：目前按实际使用场景考虑，只处理了重复提交这类情况，靠数据库唯一索引在写入时拦截，应用层没有做并发限制
- 缺的一步：**到了 1 万并发会怎么做**。补一句：
  > 真到 1 万并发，数据不会错，唯一索引兜着。压力在数据库：大量请求撞唯一索引会抛异常，连接池也可能被占满。那时我会在进库前先拦一层，比如前端防重复点击、应用层用 Redis 先判重，唯一索引留着做最后兜底。
- 详细练习材料：`../项目面试/TeamMatch-信誉与并发模拟面试.md`，其中第八节是「把信誉分迁移到游戏场景」（金币、道具、奖励都是被多个入口同时修改、每次变化都要有据可查的数值）

**⑤ AI 除了写代码，还在哪些方面提效**

- 本人答了两个：**检索**和**学习**。学习是把学习当成项目：当前基础作为输入，目标作为输出，中间分阶段
- 补强：两件事都加上「验证」
  - 检索：改简历时让 AI 把实习三个月的 80 多个提交、工作日志、周报全盘一遍，每条附提交编号或日志行号，本人抽查证据后才写进简历
  - 学习：每个阶段都有验收。AI 讲完概念，本人要用自己的话重答，AI 打分，过了才进下一阶段；进度记在文件里，下次接着走

**⑥ 前端下拉框没数据（那块后端不是本人负责）**

- 本人当时只大概说了是哪块的问题
- 补强：讲排查顺序。先看浏览器网络请求，返回为空就是后端问题；返回有数据但不显示，多半是字段名对不上（下拉组件要 `label`、`value`，后端给的是 `name`、`id`）

**⑦ 项目进度不同步怎么办（前端比后端慢两周）**

- 本人先问面试官要更多条件，对方没给，本人按通用场景答：两个方案，催前端，或者把前端的活分一部分给后端；当时选了催促
- 选择理由可以这样讲：学生项目大家都有课，每个人时间固定，后端没有余力接前端的活，硬分过去会挤占别人的时间；所以和前端沟通进度、确认卡在哪，同时后端先用 Postman 把接口自测通

**⑧ 没有前端怎么联调**

- 本人答：按详细设计文档开发，后端用 Postman 模拟前端发请求，打通 HTTP 请求到后端返回这一段
- 补两点：前端也可以先用假数据（mock）开发，谁都不卡谁；真联调仍有必要，会暴露字段格式、token 没带、分页参数理解不一致这些 Postman 测不到的问题

**⑨ 实习**

- 本人说还在职，做前端、小程序和接口开发，也讲了 MCP：OAuth 授权 → 自然语言提问 → MCP 工具调 3 张报表接口 → 返回结构化数据 → 再转成自然语言
- 下一轮可加：查询漏车的那次修复。查询默认只查一种类型、只取第一页 50 条，改成都查、自动翻页取全，并在每次回答末尾附上查询口径（时间段、条件、总条数），让用户能自己核对 AI 答得对不对。这和他们说的「让人能根据结果判断质量」是同一个思路

**⑩ 游戏**

- 报名表上填了：王者荣耀、星露谷、第五人格、金铲铲、植物大战僵尸、元气骑士、小程序游戏、鱼吃鱼，以及一些策略休闲游戏
- 只问了王者荣耀：自己玩还是一起玩、和对象玩会不会嫌对象菜。这题考的是性格（合不合群、有没有耐心），本人答得没问题

**工作流（和途游一面聊的思路一致）**
1. 两个模型各写一份「玩家预期与剧情逻辑标准」，合并成一份**统一标尺**
2. 按标尺写任务书：一个模型起草，另一个模型审查，双方确认后才执行
3. 每项任务写清**可判定的验收方式**，比如「搜索结果里不出现某些名字」「数据校验通过」
4. 标了【需拍板】的必须本人确认，AI 不能自己决定
5. 红线写死：不许碰玩家存档等目录；每批改动单独提交，有一项不通过就回滚

**1 分钟讲法**

> 我用 AI 做过一个斗罗大陆题材的文字 RPG，个人练手的同人作品，没有商用。Vue 3 加 Express，有账号和存档，三百多张配图，现在线上能玩。
>
> 代码基本是 AI 写的，我负责方向和验收。先让两个模型各写一份「玩家预期和剧情逻辑标准」，合并成统一标尺；再按标尺写任务书，一个模型起草、另一个审查，每项都写清怎么验收。执行时每批单独提交，测试、数据校验、配图审计都过了才算完成。涉及方向的决定，比如剧情要不要和原著人物绑定，必须由我拍板。

**被往深挖时要能讲到第 3～4 层的 5 个机制**（都是仓库里真实存在的）
1. 密码为什么用 scrypt 加密保存，而不是直接存
2. 登录令牌（HMAC，30 天有效）怎么验证，为什么服务器不用存
3. 存档节流：先标记「有改动」，空闲时再写盘，为什么不每次都写
4. 战斗逻辑拆成纯函数，为什么拆出来就好测试
5. 一个亲手追到根的 bug：现象 → 根因 → 怎么修 → 怎么确认修好了（从 15 份 bug 报告里挑）

真不会的地方照实说：「这块代码是 AI 写的，我验收的是它的行为是否符合预期，原理我还没深入。」

### 5.3 另一个 AI Coding 小游戏：斗地主

- 用 AI 做过一个斗地主（途游的看家产品就是斗地主）；**目前不能直接演示**，只口头讲
- 讲法：斗地主规则细节多，AI 很容易写错（顺子最少 5 张、2 和王不能进顺子、炸弹能压所有非炸弹牌型），所以先把牌型规则写成文档，再按文档逐条验收
- 怎么验收的按实际情况讲：写了测试用例就说用例，手动打牌核对就说手动核对，不说过头

### 7.2 客户端深度：不装，把网页游戏讲成客户端

核心：**网页版斗罗本身就是一个跑在浏览器里的游戏客户端**。缺的是引擎经验，不是客户端思维。

被问客户端经验时：

> 我没做过原生客户端，也没系统用过 Unity 或 Cocos。不过斗罗这个项目是网页游戏，它本身就是一个客户端：画面怎么刷新、操作之后多快有反馈、资源怎么加载、卡不卡，这些都是我自己做决策的。引擎换了，要解决的问题是一样的。

被问「为什么做客户端」：

> 休闲游戏拼的是手感和反馈，这正是客户端负责的部分。我做斗罗的时候最在意的就是玩家体验，也专门从玩家视角做过体验审查；再加上 AI 让一个人能更快上手新引擎，所以想往客户端走。

问到引擎概念不会时，用网页里的对应物接住：

| 可能问 | 接法 |
|---|---|
| 游戏主循环、帧率 | 网页里用 `requestAnimationFrame`，每帧更新状态再重新绘制，原理一样 |
| 对象池 | 频繁创建、销毁对象会触发垃圾回收，导致卡顿，所以复用对象；网页和引擎都是这个道理 |
| 资源加载 | 预加载加按需加载，先加载首屏要用的 |
| 完全没做过的 | 「这个我没实际做过，我理解它要解决的是 X，让我做的话，我会先查引擎文档，用 AI 快速验证一下」 |

原则：承认没做过，但说得出它要解决什么问题；不硬编引擎经验。
