## 大纲

1. **接口和抽象类**：
   - 接口表示一种能力或契约，一个类可以实现多个；JDK 8 起可以有 default 和 static 方法；字段都是常量
   - 抽象类表示「是什么」，只能单继承；可以有状态（成员变量）和构造器
   - 怎么选：定义规范用接口，要共享代码和状态用抽象类（模板方法模式）
2. **final**：修饰类则不能被继承，修饰方法则不能被重写，修饰变量则只能赋值一次
   - 修饰引用：引用不能再指向别的对象，但对象本身的内容可以改（集合照样能 add）
   - 想要真正不可变：用 `Collections.unmodifiableList`
3. **String 不可变**：底层数组是 final 的，而且类里没有提供修改的方法
   - 好处：可以在常量池里复用；hashCode 可以缓存（所以适合当 HashMap 的 key）；天然线程安全；作为参数传递时不会被篡改
   - 问题：频繁拼接会产生大量临时对象 → 用 StringBuilder（不是线程安全的，更快）或 StringBuffer（方法加了 synchronized）
4. **HashMap**：
   - 结构：数组 + 链表 + 红黑树（链表长度超过 8 且数组长度至少 64 时转成树）
   - put 过程：算 hash（高 16 位和低 16 位异或）→ 用 `(n - 1) & hash` 算下标 → 冲突就挂链表或树 → 元素数超过容量 × 0.75 就扩容到 2 倍
   - 可变 key：改了字段 → hashCode 变了 → 定位到别的桶 → 原来那条 get 不到也 remove 不掉，等于泄漏
   - 怎么设计：用不可变对象，或者用不会变的 id 当 key；重写 equals 和 hashCode 时只用不会变的字段
   - 大量数据：按预估数量设初始容量，避免反复扩容；保证 hashCode 分布均匀；多线程场景用 ConcurrentHashMap
5. **try-with-resources**：资源要实现 AutoCloseable，编译器会自动生成在 finally 里调用 `close()` 的代码
   - 泄漏风险：资源在 `try ()` 外面创建；包装流的构造函数抛异常时，里层的流没被关闭
   - `close()` 抛异常：如果 try 块已经抛了异常，`close()` 的异常会作为 suppressed 异常挂在主异常上（用 `getSuppressed()` 取）；如果 try 块正常结束，`close()` 的异常正常抛出
   - 多个资源按**声明的相反顺序**关闭
6. **深浅拷贝**：浅拷贝只复制引用，嵌套的对象是共享的；深拷贝的做法有手写复制构造、逐层 clone、序列化再反序列化、转 JSON 再转回来
   - N1 的 assign 指 JS 的 `Object.assign`，它是浅拷贝：改第一层属性，原对象不变；改嵌套对象的属性，原对象会跟着变
7. **10 亿条数据，array 还是 link**：选数组。数组内存连续、随机访问 O(1)、对 CPU 缓存友好；链表每个节点都有对象头加两个指针，10 亿个节点内存会爆，遍历时缓存命中率也差。另外还要注意，10 亿接近 Java 单个数组长度的上限，实际要考虑分片或外部存储
8. **序列化**：实现 Serializable，它是一个没有方法的标记接口；建议显式写 serialVersionUID；用 transient 修饰的字段不参与序列化
9. **初始化顺序**：父类静态代码块 → 子类静态代码块（类加载时只执行一次）→ 父类实例代码块 → 父类构造方法 → 子类实例代码块 → 子类构造方法

## 一句话骨架

接口是能力、抽象类是模板；final 锁的是引用不是对象；String 不可变，所以能缓存 hashCode、适合当 key；HashMap 的 key 一旦变了就找不回来；try-with-resources 会把 close 的异常挂成 suppressed。

## 易错点

- 「final 修饰的集合还能 add 吗」答成不能
- 说不清 HashMap 可变 key「找不到」的原因是 hashCode 变了
