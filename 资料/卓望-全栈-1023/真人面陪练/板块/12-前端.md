# ⑫ 前端

> 出处：N5（Vue、父传子）、N6（搜索框请求乱序、取消请求）、N4（GET 接口回显）、N1（AI 面：深浅拷贝、XSS）。编号见 `../面经原帖.md`。

## 追问链（真题）

1. Vue 是什么 → 父组件怎么把人数传给子组件（N5）
2. 搜索框先后输入 ja、java，两个请求的响应乱序回来，怎么保证最后显示的是 java 的结果（N6）
3. 怎么取消还没完成的请求（N6）
4. 除了取消请求，还有什么办法（N6）
5. 前端通过 GET 接口获取用户信息并回显的过程（N4，见 `10-场景设计.md` 大纲第 6 点）

## 大纲

1. **Vue**：渐进式框架，数据驱动视图（响应式原理：Vue 2 用 `Object.defineProperty`，Vue 3 用 `Proxy`），组件化开发
2. **组件通信**：父传子用 props；子传父用 emit 事件；跨多层用 provide / inject；全局状态用 Pinia 或 Vuex；兄弟组件通过共同的父组件或状态管理
3. **请求竞态**：
   - 根问题：后发出的请求可能先回来，先发出的请求结果把后面的覆盖了
   - 办法一：用 `AbortController.abort()` 取消上一次请求（axios 支持传 `signal`）
   - 办法二：给每次请求编号，或者记下最新的关键词，响应回来时对比，不是最新的就丢掉
   - 办法三：防抖，减少发出的请求数（只能降低概率，不能根治）
4. **备用**（原帖真人面没问到）：
   - 事件循环：先执行同步代码 → 再清空微任务（`Promise.then`）→ 再取一个宏任务（`setTimeout`）
   - 深浅拷贝：`Object.assign` 和展开运算符都是浅拷贝；深拷贝用 `structuredClone`，或者 JSON 转一圈（会丢掉函数和 undefined，Date 会变成字符串）

## 一句话骨架

父传子用 props，子传父用 emit；请求乱序的根源是后发的请求可能先回来，所以要么取消旧请求，要么只认最新那次的结果，防抖只能减少发生的概率。

## 易错点

- 把防抖当成乱序问题的根本解法

## 自测

- 口述用请求编号丢弃旧响应的实现思路
