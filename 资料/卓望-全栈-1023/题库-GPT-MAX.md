## 一、Java 基础

|---|---:|---|---|---|---|---|---|
| Java | J01 | 抽象类和接口怎么选？ | 原题 | S | 方案 | 抽象类能否多继承？接口能否有实现？ | 结论：有共享状态或模板实现选抽象类，强调能力契约和多实现选接口。抽象类只能单继承；接口支持多实现。JDK 8 接口可有 default/static 方法，JDK 9 接口私有方法。 |
| Java | J02 | 抽象类与接口的区别是什么？ | 同点变体 | S | 原理 | 接口字段是什么属性？ | 结论：抽象类可持有实例状态，接口字段默认 public static final。抽象类构造器可初始化状态；接口无实例构造器。 |
| Java | J03 | 静态代码块、实例代码块、构造方法执行顺序？ | 原题 | S | 原理 | 继承时父子类顺序如何？ | 结论：类初始化时先父类静态块，再子类静态块；创建对象时先父类实例初始化和构造，再子类实例初始化和构造。 |
| Java | J04 | Java 对象初始化顺序是什么？ | 同点变体 | S | 原理 | 静态字段何时初始化？ | 结论：首次主动使用触发类初始化；对象创建按“父类初始化→子类初始化→父类实例→父构造→子类实例→子构造”执行。 |
| Java | J05 | Java IO 模型有哪些？ | 原题 | S | 原理 | 高并发短连接下 BIO 有什么问题？ | 结论：BIO 一个连接通常占一个线程，NIO 用 Selector 复用线程，AIO 由系统完成异步通知。BIO 在高并发短连接下线程创建、上下文切换和阻塞等待成本高。 |
| Java | J06 | BIO、NIO、AIO 如何选择？ | 同点变体 | S | 方案 | Netty 主要基于哪种模型？ | 结论：低并发简单服务可用 BIO；高并发网络服务常用 NIO；AIO 依赖平台和场景。Netty 以 NIO/事件驱动为主。 |
| Java | J07 | == 与 equals 有什么区别？ | 领域高频 | A | 原理 | 为什么重写 equals 必须重写 hashCode？ | 结论：== 比较基本类型值或对象引用，equals 比较逻辑相等。相等对象必须有相同 hashCode，否则 HashMap/HashSet 行为不正确。 |
| Java | J08 | String、StringBuilder、StringBuffer 有什么区别？ | 领域高频 | A | 原理 | String 为什么不可变？ | 结论：String 不可变；StringBuilder 非线程安全、性能高；StringBuffer 方法同步、线程安全但开销更大。 |
| Java | J09 | ArrayList 和 LinkedList 如何选？ | 领域高频 | A | 方案 | ArrayList 扩容机制是什么？ | 结论：ArrayList 连续数组、随机访问快；LinkedList 双向链表、按下标访问慢。中间插入还要看定位成本，不能只按数据结构下结论。 |
| Java | J10 | HashMap 的底层结构是什么？ | 领域高频 | A | 原理 | 什么时候树化？ | 结论：JDK 8 HashMap 是数组加链表/红黑树，哈希冲突时挂桶。桶内节点数达到 8 且数组容量至少 64 时尝试树化，扩容会改变阈值。 |
| Java | J11 | HashMap 为什么线程不安全？ | 领域高频 | A | 本质原因 | 并发 put 会发生什么？ | 结论：并发读写缺少同步，可能覆盖更新、读到中间状态或扩容异常。多线程场景选 ConcurrentHashMap 或外部同步。 |
| Java | J12 | final、finally、finalize 的区别？ | 领域高频 | B | 定义 | finalize 还推荐使用吗？ | 结论：final 限制变量/方法/类；finally 用于异常收尾；finalize 是过时的回收前回调。JDK 9 已弃用，JDK 18 起不建议依赖。 |
| Java | J13 | Java 异常体系如何划分？ | 领域高频 | B | 原理 | checked 与 unchecked 如何选？ | 结论：Throwable 下分 Error 和 Exception，RuntimeException 属于非受检异常。可恢复且调用方必须处理的边界可用 checked，编程错误通常用 unchecked。 |
| Java | J14 | 重载和重写的区别？ | 领域高频 | B | 定义 | 重写时返回值和异常有什么限制？ | 结论：重载发生在同类、参数列表不同，编译期决定；重写发生在继承层次、签名相同，运行期动态分派。重写返回值可协变，不能扩大受检异常。 |
| Java | J15 | Java 泛型的类型擦除是什么？ | 领域高频 | B | 原理 | 为什么不能 new T？ | 结论：Java 泛型主要在编译期检查，运行时大多擦除为原始类型并插入强转。运行时没有具体 T 的构造器和 Class 信息。 |

## 二、JVM

| 领域 | 编号 | 题目 | 类型（原题 / 同点变体 / 领域高频） | 优先级（S / A / B） | 要懂到哪一层（定义 / 原理 / 方案 / 本质原因） | 可能的追问（1~2 个） | 答案要点（≤ 5 行，先一句话结论） |
|---|---:|---|---|---|---|---|---|
| JVM | V01 | 对象在分代内存中的晋升规则？ | 原题 | S | 原理 | 年龄如何累计？ | 结论：对象先进入 Eden，Minor GC 后存活对象在 Survivor 间复制并年龄增加，达到阈值或满足动态年龄条件后晋升老年代。 |
| JVM | V02 | JVM 怎么记录对象年龄？ | 原题 | S | 原理 | 为什么不是每次都直接晋升？ | 结论：对象头中的 GC 年龄字段随 Survivor 复制增加，HotSpot 使用对象年龄判断晋升；实际阈值受 MaxTenuringThreshold 和动态年龄判定影响。 |
| JVM | V03 | 标记清除、复制、整理的原理和优劣？ | 原题 | S | 原理 | 复制算法存活率高时为何效率低？ | 结论：标记清除回收垃圾但有碎片；复制把存活对象搬到另一块空间、无碎片但需预留空间；标记整理在原地压缩，停顿和移动成本更高。 |
| JVM | V04 | 三种 GC 算法分别适合什么区域？ | 同点变体 | S | 方案 | 老年代为什么少用复制？ | 结论：复制适合新生代低存活率；标记整理适合老年代；标记清除适合对碎片不敏感或特定阶段。老年代存活率高，复制需要搬运大量对象并准备等大空间。 |
| JVM | V05 | Minor GC、Major GC、Full GC 有什么区别？ | 同点变体 | S | 原理 | Full GC 为什么要尽量避免？ | 结论：Minor GC 主要回收新生代，Major 常指老年代回收，Full GC 回收整个堆及相关区域。Full GC 通常停顿更长，可能造成吞吐和延迟抖动。 |
| JVM | V06 | 哪些对象会进入老年代？ | 同点变体 | S | 原理 | 大对象如何处理？ | 结论：达到年龄阈值、动态年龄判定、Survivor 放不下或大对象分配策略命中的对象可能晋升。具体行为由收集器和参数决定，不能只背单一阈值。 |
| JVM | V07 | JVM 运行时内存区域有哪些？ | 领域高频 | A | 定义 | 哪些区域线程私有？ | 结论：运行时数据区包括程序计数器、虚拟机栈、本地方法栈、堆和方法区。程序计数器、虚拟机栈、本地方法栈线程私有，堆和方法区线程共享。 |
| JVM | V08 | 栈溢出和堆溢出分别如何产生？ | 领域高频 | A | 本质原因 | 如何定位？ | 结论：栈溢出常由递归过深或栈帧过大导致；堆溢出由对象持续存活或堆太小导致。用异常日志、堆转储、线程栈和 GC 日志定位。 |
| JVM | V09 | 类加载过程是什么？ | 领域高频 | A | 原理 | 双亲委派如何工作？ | 结论：类加载包括加载、验证、准备、解析、初始化。双亲委派让类先由父加载器尝试，避免核心类被应用类覆盖并减少重复加载。 |
| JVM | V10 | 什么是双亲委派模型？如何打破？ | 领域高频 | A | 原理 | SPI 为什么需要反向加载？ | 结论：类加载器先请求父加载器，父加载器无法加载时子加载器再加载。线程上下文类加载器、模块化和容器隔离都可在明确边界下改变加载路径。 |
| JVM | V11 | 强引用、软引用、弱引用、虚引用区别？ | 领域高频 | B | 定义 | ThreadLocal 为什么可能泄漏？ | 结论：强引用阻止回收；软引用内存紧张时回收；弱引用下次 GC 可回收；虚引用只用于跟踪回收并配合引用队列。 |
| JVM | V12 | 什么是安全点和安全区域？ | 领域高频 | B | 原理 | GC 如何让线程停下来？ | 结论：安全点是线程执行到可安全暂停的位置；安全区域允许线程停留在不访问堆的状态。GC 通过协作式检查和线程状态完成停顿。 |
| JVM | V13 | G1 收集器如何划分堆？ | 领域高频 | B | 原理 | G1 如何控制停顿？ | 结论：G1 将堆划分为多个 Region，按收益优先回收。通过停顿目标、记忆集和混合回收在吞吐与延迟间平衡，JDK 9 起成为默认服务端收集器。 |
| JVM | V14 | 内存泄漏与内存溢出的区别？ | 领域高频 | B | 本质原因 | 如何区分？ | 结论：内存泄漏是对象不再需要但仍被引用，长期积累可能溢出；内存溢出是申请不到足够空间。堆转储看对象存活链和占用增长。 |
| JVM | V15 | JIT 编译和逃逸分析是什么？ | 领域高频 | B | 原理 | 标量替换有什么作用？ | 结论：JIT 将热点字节码编译为机器码；逃逸分析判断对象是否逃出方法或线程。未逃逸对象可能栈上分配、锁消除或标量替换，具体由编译器决定。 |

## 三、Spring / MyBatis

| 领域 | 编号 | 题目 | 类型（原题 / 同点变体 / 领域高频） | 优先级（S / A / B） | 要懂到哪一层（定义 / 原理 / 方案 / 本质原因） | 可能的追问（1~2 个） | 答案要点（≤ 5 行，先一句话结论） |
|---|---:|---|---|---|---|---|---|
| 框架 | F01 | 依赖注入是什么，Spring Boot 怎么实现？ | 原题 | S | 原理 | 构造器注入和字段注入如何选？ | 结论：依赖注入由容器创建对象并提供依赖，Spring 通过扫描注册 Bean、解析依赖并反射或构造器完成装配。构造器注入更利于不可变和测试。 |
| 框架 | F02 | 同类型多个 Bean 且没有 @Primary / @Qualifier 时怎么处理？ | 原题 | S | 原理 | 如何按名称注入？ | 结论：按类型找到多个候选且无法消歧时抛 NoUniqueBeanDefinitionException。可用 @Primary、@Qualifier、参数名匹配或注入集合。 |
| 框架 | F03 | Spring 循环依赖哪些场景解决不了？ | 原题 | S | 本质原因 | 为什么构造器循环依赖失败？ | 结论：单例 Bean 的部分 setter/字段循环依赖可借助三级缓存提前暴露引用；构造器循环依赖、原型 Bean 循环依赖和无法提前代理的场景不能自动解决。 |
| 框架 | F04 | MyBatis 有哪些标签？ | 原题 | S | 定义 | 查询条件全为空时 SQL 是什么样？ | 结论：常用标签有 select、insert、update、delete、resultMap、sql、include、if、where、choose、foreach、set、trim。条件全空时动态标签可能生成无 WHERE SQL，需用业务校验或固定条件防误操作。 |
| 框架 | F05 | MyBatis 动态 SQL 如何避免多余 AND？ | 同点变体 | S | 方案 | `<where>` 做了什么？ | 结论：用 `<where>` 自动添加 WHERE 并移除开头 AND/OR；更新语句用 `<set>` 去掉末尾逗号。仍需防止条件全空导致全表操作。 |
| 框架 | F06 | Spring Bean 生命周期是什么？ | 领域高频 | A | 原理 | BeanPostProcessor 介入哪些阶段？ | 结论：实例化后填充属性，执行感知接口、前置处理、初始化方法、后置处理，最终进入容器；销毁时执行销毁回调。后置处理器可生成代理。 |
| 框架 | F07 | Spring AOP 的原理是什么？ | 领域高频 | A | 原理 | JDK 动态代理和 CGLIB 区别？ | 结论：AOP 将横切逻辑织入连接点，Spring 常通过代理拦截方法调用。JDK 代理要求接口；CGLIB 通过子类代理，final 类/方法不能被覆盖。 |
| 框架 | F08 | @Transactional 什么时候失效？ | 领域高频 | A | 本质原因 | 自调用为何失效？ | 结论：事务依赖代理拦截。类内自调用、非 public 方法、异常被吞掉、异常类型不匹配、代理未生效或跨线程都会导致预期事务失效。 |
| 框架 | F09 | Spring 事务传播行为有哪些？ | 领域高频 | A | 方案 | REQUIRED 和 REQUIRES_NEW 区别？ | 结论：REQUIRED 有事务就加入、无事务就新建；REQUIRES_NEW 挂起外层并新建独立事务。其他传播行为按是否加入、挂起或拒绝现有事务区分。 |
| 框架 | F10 | Spring Boot 自动配置原理？ | 领域高频 | A | 原理 | @Conditional 如何参与？ | 结论：启动时加载自动配置候选类，根据 classpath、属性和 Bean 条件选择配置。Spring Boot 2 使用 spring.factories，Spring Boot 3 使用 AutoConfiguration.imports。 |
| 框架 | F11 | Spring MVC 请求处理流程？ | 领域高频 | B | 原理 | 参数如何绑定？ | 结论：请求进入 DispatcherServlet，经 HandlerMapping 找控制器，HandlerAdapter 调用，参数解析和返回值处理后由消息转换器写响应。 |
| 框架 | F12 | MyBatis 一级缓存和二级缓存区别？ | 领域高频 | B | 原理 | 什么时候会失效？ | 结论：一级缓存按 SqlSession 生效；二级缓存按 Mapper/namespace 跨 Session 共享。更新、提交、关闭或配置变化可使缓存失效，分布式场景要谨慎。 |
| 框架 | F13 | MyBatis #{} 和 ${} 区别？ | 领域高频 | A | 本质原因 | 表名动态传入怎么办？ | 结论：#{} 使用预编译参数，能降低 SQL 注入风险；${} 直接字符串拼接，只能对受控白名单标识符使用，不能接收任意用户输入。 |
| 框架 | F14 | MyBatis 的 resultMap 解决什么问题？ | 领域高频 | B | 方案 | 一对多怎么映射？ | 结论：resultMap 用于列名与属性名不一致、嵌套对象和集合映射。一对多可用 collection，并处理主键列避免重复组装。 |
| 框架 | F15 | Spring 循环依赖为什么要三级缓存？ | 同点变体 | S | 本质原因 | 二级缓存不够吗？ | 结论：三级缓存保存 ObjectFactory，允许在提前暴露时应用 BeanPostProcessor 创建代理。只用二级缓存会过早决定原始对象，难以保证注入最终代理。 |
