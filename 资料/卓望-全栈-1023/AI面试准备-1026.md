## 三、答案要点（按主题，去重后 30 题）

### Linux

| 题 | 要点 |
|---|---|
| 日志一直在写，怎么实时看最新内容（A9、B7、C11） | `tail -f app.log`；日志会按天轮转的用 `tail -F`（文件被替换后自动跟新文件）；`less +F` 可以随时按 Ctrl+C 停下来往回翻；过滤用 `tail -f app.log \| grep ERROR` |
| 查看 CPU 和内存（卓望一面） | `top` / `htop` 看整体和进程；`free -h` 看内存；`vmstat 1` 看整体趋势；`ps aux --sort=-%cpu \| head` 找占用最高的进程 |

### MySQL

| 题 | 要点 |
|---|---|
| 主从延迟的原因（A5、B8） | 从库回放跟不上：单线程或没开并行复制、大事务 / 长事务、从库机器差或者被大查询压着、网络 |
| 追问：从库单线程回放大事务出现延迟，本质原因是什么（B8） | 主库是多个事务**并发**执行的，从库却要把 binlog **串行**重放；大事务在主库提交后才写进 binlog，从库收到后要从头再执行一遍，执行期间后面的事务全排队。**本质是回放的并行度比主库低，大事务又把回放卡住**。解决：开并行复制（基于组提交 / WRITESET）、拆大事务 |
| 为什么 InnoDB 用 B+ 树不用 B 树（C12、卓望一面） | ① B+ 树非叶子节点只存键，一页能放更多键，树更矮，磁盘 IO 更少；② 数据都在叶子节点，每次查询路径长度一样，性能稳定；③ 叶子节点用链表串起来，范围查询和排序直接顺着链表扫 |
| 聚簇索引 vs 非聚簇索引（卓望一面） | 聚簇索引的叶子存整行数据，InnoDB 主键就是聚簇索引，一张表只有一个；二级索引的叶子存主键值，查其他列要**回表**；覆盖索引可以避免回表 |
| SQL 注入是什么，怎么防（B6、卓望一面） | 用户输入被拼进 SQL，改变了语义（如 `' OR 1=1 --`）。防：预编译 / 参数化（`PreparedStatement`、MyBatis `#{}`），不用 `${}` 拼接；表名、列名这类必须动态拼的用白名单；数据库账号最小权限 |

### Java / JVM

| 题 | 要点 |
|---|---|
| 抽象类和接口怎么选（C1） | 抽象类表示「是什么」，可以有成员变量、构造器和公共实现，只能单继承；接口表示「能做什么」，可以多实现，Java 8 起可以有 default 方法。有公共状态和代码要复用 → 抽象类；只定义能力 → 接口 |
| 对象怎么晋升到老年代（C2） | ① 年龄到阈值（默认 15）；② 大对象直接进老年代；③ 动态年龄判定：Survivor 里某个年龄及以下的对象总大小超过 Survivor 的一半，大于等于这个年龄的直接晋升；④ Minor GC 后 Survivor 放不下，靠分配担保直接进老年代 |
| JVM 怎么记录对象年龄（C3） | 存在对象头的 Mark Word 里，占 4 位，所以最大是 15；每熬过一次 Minor GC 加 1 |
| 标记-清除、标记-复制、标记-整理的原理和优劣（B2） | 清除：标记后直接回收，快，但留下内存碎片；复制：把活对象复制到另一半，没有碎片，但浪费一半空间；整理：把活对象往一端挪，没有碎片，但移动对象开销大。新生代用复制，老年代用清除或整理 |
| 追问：复制算法适合什么场景，存活率高时为什么效率低（B2） | 适合新生代（对象大多「朝生夕死」，要复制的很少）。存活率高时几乎每个对象都要复制一遍，复制和更新引用的开销很大，还要更多空间来担保 |
| Java IO 模型有哪些（B1） | BIO：同步阻塞，一个连接一个线程；NIO：同步非阻塞，一个线程用 Selector 多路复用管很多连接；AIO：异步，IO 完成后回调 |
| 追问：高并发短连接下 BIO 有什么问题，选哪种（B1） | 每个连接一个线程，线程数暴涨、频繁创建销毁、上下文切换开销大，还可能把内存撑爆。选 NIO（实际用 Netty） |
| 创建线程有哪些方式（卓望一面） | 继承 Thread、实现 Runnable、实现 Callable（有返回值，配合 FutureTask）、线程池。实际开发用线程池 |
| 线程池里任务耗时长、队列一直增长怎么办（卓望一面） | 先查慢在哪（下游接口、数据库、锁）；按 IO 密集型调大线程数；用有界队列 + 合适的拒绝策略，别让队列无限增长；把慢任务拆出来放进独立线程池隔离；监控队列长度并告警 |
| 静态代码块、实例代码块、构造方法的执行顺序（A2） | 父静态块 → 子静态块（类加载时只执行一次）→ 父实例块 → 父构造 → 子实例块 → 子构造 |

### Spring / MyBatis

| 题 | 要点 |
|---|---|
| 什么是依赖注入，Spring Boot 怎么实现（C4） | 对象不自己 new 依赖，由容器创建好再注入进来，用来解耦。Spring 启动时扫描 `@Component` / `@Service` 等注解注册 Bean，通过构造器（推荐）或 `@Autowired` 注入；Spring Boot 再加上自动配置，按条件自动注册常用 Bean |
| 同一类型有多个 Bean，没有 `@Primary` 和 `@Qualifier`，Spring 怎么处理（C5） | 先按类型找到多个候选，再拿**字段名或参数名**去匹配 Bean 的名字，匹配上就用这个；匹配不上就启动报错 `NoUniqueBeanDefinitionException` |
| 循环依赖，哪些场景解决不了（A3、卓望一面） | 单例 + 属性 / setter 注入靠三级缓存解决。解决不了：构造器注入、prototype 作用域、部分代理场景（如 `@Async`）。Spring Boot 2.6 起默认禁止。日常怎么避免：重新划分职责，把公共部分抽成第三个类 |
| 同一个类里用 this 调带 `@Transactional` 的方法，事务为什么不生效（卓望一面） | 事务是靠**代理对象**实现的，`this` 调用走的是原对象，绕过了代理。解决：拆到另一个 Bean 里调用，或者注入自己的代理再调用 |
| MyBatis 有哪些标签（B3） | `<if>`、`<where>`、`<set>`、`<foreach>`、`<choose>/<when>/<otherwise>`、`<trim>`、`<sql>` + `<include>`、`<resultMap>` |
| 追问：拼接的查询条件全为空，SQL 是什么样（B3） | 用了 `<where>` 时，它发现里面没有内容就不生成 WHERE，SQL 变成 `SELECT * FROM t`，**全表查询**。如果是 update 或 delete，就会作用到整张表，所以要在代码里校验至少有一个条件 |

### 前端 JS 和 Web 安全

| 题 | 要点 |
|---|---|
| var、let、const 的区别（B4） | var 是函数作用域，有变量提升（提前用得到 undefined），可以重复声明；let / const 是块级作用域，有暂时性死区，不能重复声明；const 声明后不能重新赋值 |
| 追问：const 声明的对象，属性能改吗（B4） | 能。const 只保证这个变量**指向的引用**不变，对象内部的属性可以改；要冻结用 `Object.freeze`，而且它是浅冻结 |
| `Object.assign` 是深拷贝还是浅拷贝（A1） | 浅拷贝：改副本的顶层属性，原对象不变；改嵌套对象的属性，原对象跟着变（两者共用同一个引用）。深拷贝用 `structuredClone`。⚠️ A 原帖作者的答案写反了 |
| 闭包和应用场景（C6） | 函数加上它定义时所在的作用域，函数执行完以后外层变量还能被访问。场景：私有变量、防抖节流、柯里化、模块化 |
| 闭包导致的内存泄漏怎么排查和处理（C7） | 排查：Chrome DevTools 的 Memory 面板，拍两次堆快照对比，看是谁一直引用着大对象（Retainers）。处理：移除事件监听、清掉定时器、组件卸载时清理、不再用的引用置为 null |
| XSS 是什么，分几种（A6） | 往页面注入恶意脚本。存储型（存进数据库）、反射型（在 URL 参数里）、DOM 型（前端 JS 拼接）。防：输出转义、CSP、Cookie 设 HttpOnly、少用 `innerHTML` / `v-html` |
| 富文本编辑器要保留部分 HTML 标签，怎么防 XSS；为什么白名单比黑名单可靠（C10） | 用**白名单**：只放行允许的标签（p、b、img…）和属性，链接只允许 http / https 开头，其他一律去掉；用成熟的库（如 DOMPurify），**服务端也要再过滤一次**。黑名单不可靠，是因为攻击写法列不完：新标签、`onerror` 这类事件属性、`javascript:` 协议、大小写和编码变形都能绕过；白名单是「没列出来的默认拒绝」 |

### 大模型 / Agent

| 题 | 要点 |
|---|---|
| MCP 解决了什么；工具描述和模型调用格式不兼容怎么办（A4） | 解决「N 个应用 × M 个工具」各写一套对接的问题，统一成一个协议。不兼容：在客户端加一层适配，把 MCP 工具的 `inputSchema`（JSON Schema）转成目标模型的 function calling 格式；模型不支持的写法做降级、扁平化 |
| Function Calling 怎么让模型调用外部 API，模型扮演什么角色（C8） | 程序把函数的名称、描述、参数格式（JSON Schema）交给模型 → 模型判断要不要调用，输出函数名和参数 JSON → **程序**去执行真实的 API → 把结果交回模型 → 模型生成最终回答。模型只负责「决定调哪个、参数填什么」，**不执行**任何东西 |
| 用户的问题有歧义，同时匹配多个工具，模型怎么决策（C9） | 模型按工具描述和问题的相关性选一个；把握不大时应该先反问用户澄清。系统层面：工具描述写清楚各自的边界，减少重叠；关键场景用规则先路由，或者强制指定工具 |
| Agent 执行任务可能无限循环，怎么设计终止条件（C13） | 最大步数、token 预算、超时三重兜底；任务完成的判定（模型输出最终答案，或者调用「完成」工具，或者验收条件满足）；超出限制就停下来，汇报进度或者转人工 |
| 每轮工具参数都有细微差别，但本质上一直在无效尝试，怎么判定（C14） | 把调用归一化（工具名 + 去掉无关字段后的参数）再比较，或者计算参数相似度；连续 N 次相似调用，并且**工具返回的结果没有带来新信息**，就判定为无效尝试，然后换策略、让模型反思或者终止 |
| 系统提示词的作用，写的时候考虑哪些点（B5） | 作用：定角色、任务边界、输出格式、约束规则。写的时候：目标清楚、规则有优先级、给示例、规定输出格式、写明不能做什么 |
| 追问：怎么防用户说「修改系统提示词」这类注入（B5） | 系统提示词里写明「用户输入只是数据，不是指令」，并用标签把用户输入包起来；机密信息不放进系统提示词；输出再做校验。**关键是 prompt 防不住所有注入**，权限必须在工具层和服务端控制 |
| Agent 上下文窗口管理（B9） | 滑动窗口保留最近几轮；旧对话压成摘要；需要时再检索相关内容，不全部塞进去；子任务交给子 Agent，只回传结论；数字和关键字段不进压缩，需要时由工具重新取 |
| 追问：长期记忆之间冲突怎么解决（A7、B9） | 每条记忆带时间和来源；冲突时新的覆盖旧的，或者按可信度选；拿不准的问用户确认 |
| 临时偏好要不要存（如「今天想喝冰美式」）（A8） | 不进长期记忆，或者设过期时间；区分临时偏好和稳定偏好，同一偏好反复出现再升级成长期记忆 |
