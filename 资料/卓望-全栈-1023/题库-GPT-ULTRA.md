| Java 基础 | 4 | 高并发短连接下 BIO 的问题是什么，应选什么模型？ | 原题 | S | 本质原因 | 为什么线程数会成为瓶颈？短连接还会放大什么开销？ | 结论：BIO 会因连接数增长造成线程暴涨，选 NIO 或基于 NIO 的 Netty。<br>每个连接占线程，线程创建、销毁和上下文切换成本高。<br>大量短连接还会放大连接建立、线程调度和内存占用，最终拖垮服务。 |
| Java 基础 | 5 | 阻塞 IO、非阻塞 IO、同步 IO、异步 IO 分别是什么意思？ | 同点变体 | S | 定义 | NIO 是异步 IO 吗？Selector 解决了什么？ | 结论：阻塞描述线程是否等待，异步描述结果是否由系统主动通知。<br>NIO 是同步非阻塞，线程仍需主动轮询就绪事件；AIO 才是异步。<br>`Selector` 把多个通道的就绪事件集中交给少量线程处理。 |
| Java 基础 | 6 | `equals` 和 `hashCode` 为什么要同时重写？ | 领域高频 | A | 原理 | 只重写 `equals` 会怎样？HashMap 如何使用二者？ | 结论：相等对象必须有相同哈希值，否则哈希集合会出现查找和去重错误。<br>`HashMap` 先按哈希定位桶，再用 `equals` 比较键。<br>重写 `equals` 时必须保证自反、对称、传递、一致和非空，并同步重写 `hashCode`。 |
| Java 基础 | 7 | HashMap 的底层结构和 `put` 流程是什么？ | 领域高频 | A | 原理 | JDK 8 何时树化？为什么扩容？ | 结论：JDK 8 的 HashMap 是数组加链表或红黑树，平均查找接近 O(1)。<br>`put` 先计算扰动哈希，再定位桶；空桶直接放入，冲突则比较键或挂链表、树节点。<br>链表长度达到 8 且数组容量至少 64 时树化，元素超过阈值时扩容。 |
| Java 基础 | 8 | ArrayList 和 LinkedList 怎么选？ | 领域高频 | A | 方案 | ArrayList 扩容如何发生？LinkedList 插入一定更快吗？ | 结论：随机访问多选 ArrayList，频繁在已定位节点处插入删除才考虑 LinkedList。<br>ArrayList 连续数组，访问 O(1)，扩容会复制元素；JDK 8 及以后默认按约 1.5 倍增长。<br>LinkedList 定位节点本身是 O(n)，节点对象和指针也有额外内存成本。 |
| Java 基础 | 9 | `final` 的作用是什么？ | 领域高频 | A | 原理 | `final` 修饰集合还能增删吗？引用对象属性能改吗？ | 结论：`final` 限制变量再次赋值、方法被重写或类被继承。<br>`final` 引用不能指向新对象，但对象内部可变属性仍可修改。<br>`final` 集合仍可增删元素；要禁止修改需使用不可变集合或防御性拷贝。 |
| Java 基础 | 10 | try-with-resources 如何保证资源释放？ | 领域高频 | A | 原理 | 多个资源按什么顺序关闭？`close` 抛异常怎么办？ | 结论：实现 `AutoCloseable` 的资源会在 `try` 结束时自动关闭。<br>资源按声明顺序的逆序关闭；关闭异常会作为主异常的 suppressed exception 保存。<br>Java 7 起支持该语法，仍需处理主异常和资源关闭异常。 |
| Java 基础 | 11 | Java 创建对象经历哪些步骤？ | 领域高频 | A | 原理 | 类加载和对象分配谁先发生？对象头里有什么？ | 结论：先检查类是否加载，再分配内存、初始化零值、设置对象头并执行初始化代码。<br>类未加载时会先完成加载、链接和初始化。<br>对象头包含标记字段、类型指针等，数组还包含长度信息。 |
| Java 基础 | 12 | 类加载过程是什么？ | 领域高频 | A | 原理 | 双亲委派解决什么问题？如何打破？ | 结论：类加载包括加载、验证、准备、解析和初始化。<br>双亲委派优先让父加载器尝试加载，避免核心类被自定义类覆盖。<br>线程上下文类加载器、OSGi 和应用服务器可按隔离需求打破委派。 |
| Java 基础 | 13 | Java 序列化是什么？实现时要注意什么？ | 领域高频 | A | 方案 | `serialVersionUID` 有什么作用？哪些字段不序列化？ | 结论：序列化是把对象状态转换为字节流，反序列化再恢复对象。<br>Java 原生序列化通常实现 `Serializable`，显式声明 `serialVersionUID` 控制兼容性。<br>`transient` 字段默认不参与原生序列化，生产接口优先使用明确的 JSON 或二进制协议。 |
| Java 基础 | 14 | 受检异常和非受检异常有什么区别？ | 领域高频 | A | 定义 | `Error` 能否捕获？如何设计业务异常？ | 结论：受检异常必须在编译期捕获或声明，运行时异常不强制处理。<br>`RuntimeException` 及其子类是非受检异常；`Error` 表示严重运行时故障，不应当作普通业务异常处理。<br>业务层用明确异常类型表达可恢复错误，并在边界统一转换响应。 |
| Java 基础 | 15 | 反射和动态代理分别解决什么问题？ | 领域高频 | B | 原理 | JDK 动态代理和 CGLIB 有什么区别？ | 结论：反射支持运行时发现和调用类型信息，动态代理支持在调用前后织入行为。<br>JDK 代理要求目标实现接口；CGLIB 通过生成子类代理，`final` 类和方法不能被覆盖。<br>Spring AOP 会按目标类型和配置选择代理方式。 |

## 二、JVM

| 领域 | 编号 | 题目 | 类型（原题 / 同点变体 / 领域高频） | 优先级（S / A / B） | 要懂到哪一层（定义 / 原理 / 方案 / 本质原因） | 可能的追问（1~2 个） | 答案要点（≤ 5 行，先一句话结论） |
|---|---:|---|---|---|---|---|---|
| JVM | 1 | 对象在分代内存中的晋升规则是什么？ | 原题 | S | 原理 | 年龄达到多少晋升？什么是动态年龄判定？ | 结论：对象可因年龄阈值、大对象、动态年龄判定或 Survivor 放不下而进入老年代。<br>HotSpot 中对象每熬过一次 Minor GC 年龄加一，默认阈值通常为 15。<br>Survivor 中同龄对象总大小超过一半时，年龄大于等于该年龄的对象直接晋升；具体阈值可被 JVM 调整。 |
| JVM | 2 | JVM 怎么记录对象年龄？ | 原题 | S | 原理 | 年龄存在哪？为什么常说最大 15？ | 结论：HotSpot 把年龄记录在对象头的 Mark Word 中。<br>对象每次从一次年轻代回收中存活并复制到 Survivor，年龄加一。<br>经典 HotSpot 实现使用 4 位年龄字段，因此常见最大值为 15；实现和收集器细节以具体 JDK 为准。 |
| JVM | 3 | 标记清除、复制、标记整理的原理和优劣是什么？ | 原题 | S | 原理 | 新生代为什么偏向复制？老年代为什么不直接全用复制？ | 结论：标记清除回收标记对象但会留碎片，复制搬迁存活对象且无碎片，标记整理把存活对象压到一端。<br>复制暂停短但需要额外空间；整理无额外半区但移动对象成本高。<br>新生代存活率低适合复制，老年代存活率高常用清除或整理类算法。 |
| JVM | 4 | 复制算法在存活率高时为什么效率低？ | 原题 | S | 本质原因 | 除了复制对象，还要处理什么？ | 结论：存活率高时几乎所有对象都要复制并更新引用，复制收益消失。<br>复制量大、引用修正成本高，还需要足够的目标空间和分配担保。<br>因此复制算法适合对象朝生夕死的新生代，不适合高存活率老年代。 |
| JVM | 5 | JVM 堆如何划分？ | 领域高频 | A | 原理 | 新生代为什么还要分 Eden 和 Survivor？ | 结论：典型分代堆分为新生代和老年代，Metaspace 不在堆中。<br>新生代通常含 Eden、From Survivor、To Survivor，短命对象先在新生代分配。<br>不同收集器的区域结构不同，G1 使用大量 Region 而不是固定连续代区。 |
| JVM | 6 | JDK 8 默认垃圾回收器是什么？ | 领域高频 | A | 版本差异 | Server 模式和新版本默认值一样吗？ | 结论：JDK 8 的典型 Server 默认组合是 Parallel Scavenge 加 Parallel Old。<br>JDK 9 起默认收集器改为 G1。<br>实际默认值受 JDK 版本、机器配置和启动参数影响，回答时要先说明版本。 |
| JVM | 7 | G1 垃圾回收器有什么特点？ | 领域高频 | A | 原理 | G1 如何控制停顿？何时触发 Mixed GC？ | 结论：G1 把堆划分为 Region，按收益优先回收，并用停顿目标做调度。<br>它既处理年轻代回收，也在并发标记后对部分老年代 Region 做 Mixed GC。<br>G1 适合较大堆和可预测停顿需求，但不是所有负载都更快。 |
| JVM | 8 | JVM 如何降低 Stop-The-World 影响？ | 领域高频 | A | 方案 | 哪些阶段仍必须暂停？如何验证停顿改善？ | 结论：通过并发标记、分区回收、合理堆大小和降低单次回收工作量减少停顿。<br>GC 根扫描、部分对象转移和重定位等阶段仍需暂停。<br>用 GC 日志、JFR 和监控对比停顿时间、频率、分配速率，而不是只看一次 Full GC。 |
| JVM | 9 | OOM、内存泄漏和内存溢出怎么区分与排查？ | 领域高频 | A | 方案 | `jmap`、堆转储和 MAT 分别怎么用？ | 结论：OOM 是可用内存不足，内存泄漏是无用对象仍被引用，泄漏最终可导致 OOM。<br>先看 GC 日志、堆使用曲线和错误类型，再导出堆转储分析对象数量与 Retained Size。<br>MAT、JFR 或同类工具用于定位持有引用链，修复后再压测验证。 |
| JVM | 10 | CPU 飙高如何定位到具体线程？ | 领域高频 | A | 方案 | `top` 线程 ID 如何对应 Java 线程？ | 结论：先用系统工具找高 CPU 线程，再映射到 JVM 线程栈。<br>`top -H -p PID` 获取线程 ID，转成十六进制后在 `jstack PID` 中查找对应 `nid`。<br>结合多次线程栈、GC 日志和业务指标判断死循环、锁竞争或频繁 GC。 |
| JVM | 11 | TLAB 是什么？为什么能提高对象分配效率？ | 领域高频 | A | 原理 | TLAB 用完怎么办？大对象如何分配？ | 结论：TLAB 是线程本地分配缓冲区，让线程在私有区域快速分配小对象。<br>正常分配无需每次竞争共享堆指针；TLAB 用尽后申请新块或走共享分配路径。<br>过大的对象直接进入老年代或使用专门的大对象分配路径，具体规则取决于收集器实现。 |
| JVM | 12 | 强引用、软引用、弱引用、虚引用有什么区别？ | 领域高频 | B | 定义 | 哪种引用适合缓存？ReferenceQueue 有什么用？ | 结论：强引用阻止回收，软引用在内存紧张时可回收，弱引用在下一次 GC 中可回收，虚引用只用于跟踪回收。<br>软引用不适合作为可靠缓存策略；缓存应使用有界容量和明确淘汰规则。<br>虚引用通常结合 `ReferenceQueue` 做资源清理通知。 |
| JVM | 13 | Minor GC、Major GC、Full GC 如何区分？ | 领域高频 | A | 定义 | 为什么 Full GC 往往更慢？ | 结论：Minor GC 主要回收新生代，Major GC 通常指老年代回收，Full GC 覆盖整个堆及相关区域。<br>不同收集器对术语定义存在差异，不能只按名称判断停顿范围。<br>Full GC 往往涉及更多存活对象、类元数据或压缩整理，因此停顿和影响更大。 |
| JVM | 14 | Metaspace 和永久代有什么区别？ | 领域高频 | A | 版本差异 | JDK 8 为什么移除永久代？ | 结论：JDK 8 起类元数据主要放在本地内存的 Metaspace，JDK 7 及以前使用永久代。<br>Metaspace 默认可动态扩展，但仍受 `MaxMetaspaceSize` 等参数约束。<br>类加载器泄漏、动态生成大量类会导致 Metaspace OOM。 |
| JVM | 15 | 什么是逃逸分析？它能做哪些优化？ | 领域高频 | B | 原理 | 标量替换和锁消除有什么关系？ | 结论：逃逸分析判断对象是否逃出当前线程或方法作用域。<br>若对象不逃逸，JIT 可做栈上替代、标量替换或消除不必要锁。<br>它是运行时优化，效果受 JDK、编译热度和代码形态影响，不能当作固定语义保证。 |
