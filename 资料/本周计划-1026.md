## 四件事

| 事项 | 现在的问题 | 做完的样子 |
|---|---|---|
| **① 数据库设计**（一面弱项） | 一面只答了「按范式，AI 生成，我按数据流核对」，太空 | 能讲清 5～6 张核心表：为什么这么拆、唯一索引防什么、哪些字段冗余以及为什么、怎么验证设计是对的 |
| **② 技术落地**（TeamMatch 核心） | 业务和核心逻辑能讲清；技术实现讲得宽泛，概念乱套 | 互评提交、信誉分更新、复核/申诉恢复 3 条链路，每条都能从接口讲到 SQL |
| **③ 举例子**（一面弱项） | 补录上传的例子没先给结论 | 3 个例子，都按「结论 → 问题 → 排查 → 处理 → 结果」讲，每个约 1 分钟 |
| **④ MCP** | 这周边开发边准备 | 每天开发完记 3 行（做了什么、遇到什么坑、怎么解决）；周末整理成 2 分钟讲稿：为什么用 MCP 不用普通 API、工具怎么设计、出错和权限怎么处理、怎么验证效果 |

**② 的答题模板**（每条链路都按这个顺序）：接口入参 → 在哪一层校验 → 事务里依次执行哪几条 SQL → 用了哪些索引或锁 → 两个请求同时进来会怎样 → 出错返回什么

**练法**：我先讲，AI 按二面的强度追问，追到答不上来为止，再一起把那个口径补上。
