### 已知 AI 面真题（10-17，卓望 AI 面，作者 Java 方向，岗位未写）

来源：牛客《移动卓望AI面10.17》https://www.nowcoder.com/feed/main/detail/2dcc16b1678d42beac2c7f5270f6ff0c （10-26 打开核对，9 题和下表一致）。GPT 10-26 检索的其他结论：每题时限、视频还是语音、能否重答，都**未找到证据**；牛客官方说明 AI 面试支持「根据回答实时追问」，所以每题都要准备被追问一层。

| # | 题目 | 答案要点 |
|---|---|---|
| 1 | 深拷贝和浅拷贝；`Object.assign` 之后改对象属性，原对象会变吗 | `assign` 是浅拷贝：**改副本的顶层属性，原对象不变；改嵌套对象的属性，原对象跟着变**（共用同一个引用）。⚠️ 原帖作者的答案写反了。深拷贝用 `structuredClone` 或递归复制 |
| 2 | 静态代码块、实例代码块、构造方法的执行顺序 | 父类静态块 → 子类静态块（只在类加载时执行一次）→ 父类实例块 → 父类构造 → 子类实例块 → 子类构造 |
| 3 | Spring 循环依赖，哪些场景解决不了 | 单例 + 属性 / setter 注入靠三级缓存解决。解决不了：构造器注入、prototype 作用域、部分代理场景（如 `@Async`）。Spring Boot 2.6 起默认禁止循环依赖 |
| 4 | MCP 解决了什么；MCP 返回的工具描述和模型的调用格式不兼容怎么办 | 解决「N 个应用 × M 个工具」各写一套对接的问题，统一成一个协议。不兼容：在客户端加一层适配，把 MCP 工具的 `inputSchema`（JSON Schema）转成目标模型的 function calling 格式；模型不支持的 schema 写法要做降级、扁平化 |
| 5 | MySQL 主从延迟的原因 | 从库回放慢（单线程或并行复制没开）、大事务 / 长事务、从库配置差或者被大查询压着、网络。解决：开并行复制、拆大事务、刚写完马上要读的走主库 |
| 6 | XSS 是什么，分几种 | 往页面注入恶意脚本。三种：存储型（存进数据库）、反射型（在 URL 参数里）、DOM 型（前端 JS 直接拼接）。防：输出转义、CSP、Cookie 设 HttpOnly、少用 `innerHTML` / `v-html` |
| 7 | Agent 长期记忆存哪些；记忆冲突怎么办 | 存：用户画像和稳定偏好、事实、重要事件的摘要。冲突：每条记忆带时间和来源，新的覆盖旧的；拿不准的问用户确认 |
| 8 | 临时偏好要保存吗（如「今天想喝冰美式」） | 不进长期记忆，或者设置过期时间；要区分「临时偏好」和「稳定偏好」，同一偏好反复出现再升级为长期记忆 |
| 9 | 怎么实时读取 Linux 日志 | `tail -f`（日志文件会轮转时用 `tail -F`）；配合 `grep` 过滤，例如 `tail -f app.log \| grep requestId` |
