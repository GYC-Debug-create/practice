## 蓝色光标 AI Builder：经历问答冲刺

本岗位材料强调需求分析、方案权衡、AI 产品原型到交付、效果评估和持续迭代。以下是从已有面试题与个人项目记录提炼的练习问题，不是本次 AI 面试原题。

| 练习问题 | 回答准备抓手 | 事实材料 |
|---|---|---|
| 介绍一个你独立完成的 AI 应用或 AI Coding 项目 | 用户/问题 → 目标和边界 → 方案 → 自己负责的决定 → AI 参与部分 → 验收与迭代 → 结果/局限 | 斗罗独立 Vibe Coding 项目；家庭斗地主是规则驱动牌局 AI，不是 LLM 对话产品；[AI 协作资料库](https://github.com/GYC-Debug-create/how-to-use-ai-in-projects) |
| 需求模糊时，怎么把它变成可交付功能？ | 先问目标用户、输入输出和边界；列验收标准与风险；切成可运行小步；每步验证 | [快手一面复盘](快手-AI全栈-1022/面试记录/一面-1022.md) |
| AI 生成代码后，你如何判断是否能交付？ | 人工预期、正常/边界/异常用例、独立审查、换数据复测；讲一个真实发现的问题 | 快手现场校验器复盘；TeamMatch 异常评价案例见 [记忆记录](快手-AI全栈-1022/memory.md) |
| 上线后发现漏测 badcase 怎么办？ | 先止血；复现并定位；修复；把 case 纳入回归集；检查验收标准/测试流程为什么漏掉 | [AI 概念对照表](快手-AI全栈-1022/板块/04-AI概念/概念对照表.md) |
| 如何设计 AI 应用效果指标？ | 先定义任务成功标准；离线用例评准确性/覆盖率/延迟/成本；上线看完成率、采纳率、转人工率、投诉与成本；按 badcase 迭代 | [AI 概念对照表](快手-AI全栈-1022/板块/04-AI概念/概念对照表.md)；未上线项目不要编造线上数据 |
| Agent 和普通 Chat 的差别？如何防止失控？ | 讲模型决策、工具执行、结果观察和多步循环；权限放在工具/服务端，设置预算、超时、步数、人工确认和日志 | 同上；按真实实践说明做过/没做过 |
| MCP、Function Calling、Skill 各解决什么？ | Function Calling 是模型输出调用意图、应用执行；MCP 统一工具/资源协议；Skill 是可按需加载的方法和资料 | [AI 概念对照表](快手-AI全栈-1022/板块/04-AI概念/概念对照表.md) |
| AI 的局限是什么？怎样处理幻觉？ | 不把概率生成当事实；限制上下文和权限；要求引用/结构化输出；用工具核对；关键结果人工审核 | [AI 概念对照表](快手-AI全栈-1022/板块/04-AI概念/概念对照表.md) |

回答统一用“结论 → 真实例子 → 我做的判断/验证 → 局限”，不宣称没做过的上线、指标或团队职责。
