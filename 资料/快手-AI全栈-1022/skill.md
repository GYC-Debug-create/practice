# skill.md — 通用方法

## 一、四层准备法（板块 2、3、4 必用）

每个要讲的点都准备到四层。面经里面试官就是这样一层层追问的（例：B 三面、F）。

| 层 | 问法 | 要准备的 |
|---|---|---|
| 1 做了什么 | 这块是干嘛的？你负责什么？ | 30 秒说清楚，带一个具体场景 |
| 2 为什么 | 为什么这么做？有别的方案吗？ | 至少一个备选方案 + 为什么没选 |
| 3 坏了怎么办 | 并发、异常、用户乱输入、下游挂了、被绕过 | 一个具体的失败场景 + 怎么兜住 |
| 4 怎么证明 | 怎么知道是对的？效果怎么评估？ | 测试、数据、证据（文件或提交号） |

面试官偏好：**能靠工程保证的，不靠 prompt 约束**（真题 B 三面、G、F）。

## 二、真题怎么用

- 每个板块文件都列了对应的真题。执行对话必须逐题过一遍：能用自己经历答的，写答案要点；答不了的，写进「还讲不清」
- 真题里问的是别人的项目，要换成自己的项目来答。例：B 问「Multi-Agent 怎么调度」→ 你答用友多模型协作怎么分工
- 模拟面试从真题里抽题，加上对你简历的追问

## 三、交回模板（执行对话结束时输出，用户贴回总指挥）

```
## 交回：板块 0X <名称>
- 日期：
- 产出文件：<路径，逐个列>
- 真题覆盖：对应 N 题，已准备 M 题；没准备的：<列出>
- 能讲清的：<逐条，一句话一条>
- 还讲不清 / 没把握的：<逐条>
- 需要写进 memory 的：<新确认的口径、事实、措辞调整>
```

## 四、验收标准（总指挥用）

1. **抽查 1~2 处**：产出里引用的源码行号、素材条目、数字，对原文核实
2. **真题覆盖**：对应真题都有答案要点，或明确列为「讲不清」
3. **没有编造**：项目里没做过的不许写成做过；YonWork 没投产，不许说线上指标
4. **口径一致**：和 `memory.md` 里已确认的口径不冲突
5. 通过 → 板块状态改为「已验收」；不通过 → 写明问题，退回执行对话

## 五、措辞规范

- 说「AI 辅助开发」，不说「vibe coding」
- 说「框架层面借助 AI，设计和把关由我负责」，不说「技术不行」
- YonWork 权限：说「用户用自己的账号登录，系统里没权限的报表在 YonWork 里也查不到」（有测试证据）；不说「只能看到自己组织的数据」（后端没做）
- 说人话，先结论后细节；一个回答控制在 1~2 分钟
